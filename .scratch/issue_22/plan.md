## Verify 阶段的执行顺序

1. 运行 T2–T5 的隔离回归，按 A1–A8 留存正反例的命令、退出码、诊断和计数。分别断言 ORG005 与 ORG008，防止把已解析但无规则的组件误计为已检查。
2. 在干净的消费环境验证构建包、公共导入、四个注册 ID 及相应配置；在另一包名的项目用固定修订接入 hook。分别验证目录正确、实现错放和仅删除目标文件三种情况。
3. 在完整仓库运行 `isaaclab-task-lint`、`ruff check .`、`pre-commit run --all-files` 及现有回归测试。记录发现的环境与组件数，对照 T1 防止漏扫；组织违规、未解析及缺规则三项均须为零。若格式 hook 修改文件，复核差异并重新运行全套适用检查。记录实际执行命令和返回值。
4. 对照 T1 核验配置与行为，逐项在 `verification.md` 记录 A1–A8 的证据及偏差。静态检查和跨项目样例使用 CPU；若需执行仿真回归，先查 RAM/VRAM，再串行运行有时限的 headless 小规模任务，默认 2 个环境。
