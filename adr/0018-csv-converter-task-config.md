# 实机 CSV 从注册任务读取关节分组

**状态：Accepted。** Q10 分组规则已获用户明确批准：“由任务配置决定每个关节使用位置还是速度，以及它在输出中的列序；csv表头决定实际记录哪些关节”。随后用户明确批准“ADR 0018 中直接读取注册任务配置，其余配套接口及 CR7-A1–A5，并进入 Plan”。

**背景。** CSV 已用完整关节名标识列。给定样例存放在 X5 目录，四个名称却属于 X3mini。拟合文件用张量列号表示信号，关节名和组别由任务配置解释。转换时选错物理量或组内顺序会使实测值对应到错误的关节。[参考数据语义](0009-reference-semantics-in-fit-config.md) · [样例核对](../.scratch/issue_4/research.md#样例反馈与字段)

**备选方案。** 直接加载注册的环境配置可取得任务默认分组与控制周期；沿用拟合的 Hydra 解析器还可处理命令行配置覆盖。单独维护机器人映射表需要在任务改名或改组时同步。名称中的 `foot/wheel` 可识别现有轮式任务；命名习惯本身无法描述每个自定义任务的控制方式。[配置读取比较](../.scratch/issue_4/research.md#任务配置的可行读取路径) · [既有关节契约](0008-canonical-joint-groups-and-layout.md)

**决定及理由。** 在独立转换入口发现已注册的任务、读取其默认环境配置，并复用项目完整关节分组。表头决定记录了哪些关节，任务决定它们的物理量和组内列序；自定义任务分组与名称惯例相冲突时也按任务声明。这样同一个任务负责转换和拟合两侧的名称解释，读取配置只需项目的 Python 环境。

**影响与权衡。** 转换机器需要安装项目及 Isaac Lab 配置依赖；转换时无需加载机器人场景或运行仿真。输出打印实际列序，便于操作者把同一声明传给拟合；表头中不属于任务的关节会显式报错。[已批准接口](../.scratch/issue_4/interfaces.md#cr7-csv-转换接口)
