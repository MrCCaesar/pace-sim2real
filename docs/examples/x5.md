# X5 native MuJoCo data collection

Collect twelve leg-joint position responses and four wheel-joint velocity responses using native MuJoCo, independently of the Isaac Lab launcher. The mixed dataset can be fitted with a matching Isaac Lab position/velocity task; declare its column order and unified feedback bias semantics in the fit configuration. Old measurement-only-bias datasets must be recollected.

## Requirements

Use Python 3.12 with MuJoCo 3.17.0, NumPy and PyTorch. Matplotlib is needed only for plotting. The existing project environment supplies these dependencies. The collector runs from a source checkout; no Isaac Lab modules are imported by its entry point.

Supply the user-owned model and its referenced mesh resources at:

```text
src/pace_sim2real/assets/data/robots/sevnce/x5/mjcf/x5_calibration.xml
```

The model resources are local inputs and are not bundled by this change. Alternatively, point a custom TOML configuration at your model. Model paths in TOML are relative to that TOML file; the default configuration is resolved relative to the source checkout, independently of the working directory.

## Collect

```bash
.venv/bin/python scripts/pace/data_collection_mujoco.py
```

Defaults are a linear chirp from 0.1 to 10 Hz for 20 seconds, with seed 42. Plotting follows `run.plot` in your configuration; live visualization is disabled by default. For a bounded smoke run:

```bash
PACE_ROOT=/tmp/x5-smoke .venv/bin/python scripts/pace/data_collection_mujoco.py --duration 0.1
```

The normal destination is `data/x5_sim/chirp_data.pt` under the project root. `PACE_ROOT` overrides this output root. Data are written only after complete successful collection: a temporary sibling file is serialized and atomically replaces the destination. Failed collection or interrupted/failed saving preserves any previous dataset. A plotting failure occurs after saving and does not invalidate that saved dataset.

## Configure

Edit `config/x5_collection.toml`, or pass `--config PATH`. All sections and baseline keys are required; unknown keys are errors. The new direction arrays and `run.visualize` are optional for compatibility with older configurations. CLI options `--min_frequency`, `--max_frequency`, `--duration` and `--plot` override the corresponding TOML values. `--plot` enables plotting; to disable it, use `plot = false` in TOML and omit the flag.

- `[run]`: frequency endpoints in Hz, duration in seconds, integer random seed and independent plotting/live-visualization switches. Require `0 < min_frequency <= max_frequency < 1/(2*dt)` and a positive integer number of simulation steps (duration/dt tolerance: 1e-9).
- `[model]`: MJCF path. The model owns the timestep, integrator, native PD/force limits, actuator delay/history, passive damping, armature, dry friction and sensor noise metadata. The collector does not override these properties.
- `[trajectory]`: twelve dimensionless position center coefficients, position amplitudes in radians and four wheel-speed amplitudes in rad/s. Each leg defaults to centers `[0, 0.4, -1.4]` and amplitudes `[0.25, 0.5, 0.99]`; wheels have zero center and amplitude 10. Targets use `(center + sin(phase)) * amplitude * direction`; the physical center is therefore coefficient times amplitude times direction. All channels share the chirp phase. There is no automatic clipping or recentering.
- `[measurement]`: encoder bias in radians, either one scalar for all twelve leg channels or twelve values. Default is 0.05. Position measurement is **sensor reading minus encoder bias plus noise**. Wheel velocity measurement is **sensor reading plus noise**.
- `[channels]`: explicit ordered leg and wheel joint names. Legs are FL, FR, RL, RR, each hip/thigh/calf; wheels are FL, FR, RL, RR. Actuator and sensor IDs are resolved by their associated joints, not assumed to match body traversal order.

Noise is independent zero-mean Gaussian measurement noise. Standard deviations come from each XML sensor's `noise` attribute (the provided model has position 0.01 rad and wheel velocity 0.1 rad/s). MuJoCo 3.17 stores these values but does not inject noise itself; the collector injects it once using a local seeded generator. Random noise does not change feedback. Encoder bias does: the native position-servo control is desired position plus bias, equivalent to feeding back physical position minus bias. Unsupported mappings or control clipping are rejected.

The supported model has a fixed base, sixteen scalar hinge joints and one unit-gear native position/velocity servo and matching instantaneous joint sensor per collected joint. Unsupported transmissions, filtered actuators, delayed/interval sensors and insufficient actuator-history capacity fail explicitly. They are not approximated by a different model.

## Independent trajectory directions

`trajectory.position_directions` has 12 signs in leg-channel order, and `trajectory.velocity_directions` has 4 in wheel-channel order. Each value must be numeric `+1` or `-1`; booleans, other values and wrong lengths are rejected before sampling. Both default to all `+1` when absent, including for existing Python `CollectionConfig` callers.

For legs, the target is `(center + sin(phase)) * amplitude * direction`. Thus coefficient `0.4`, amplitude `0.5` and direction `-1` produce a desired center of `-0.2` rad; the oscillation reverses too. Wheel targets are `direction * amplitude * sin(phase)`. Choose signs explicitly for your robot; no left/right pattern is inferred. Initial physical leg positions and native control history use the first desired target plus encoder bias. Sensor readings, encoder correction and noise retain the original MJCF joint coordinates. Desired tensors contain signed commands before actuator delay. Mirrored trajectories still require the model owner's physical assessment.

## Live observation

```bash
.venv/bin/python scripts/pace/data_collection_mujoco.py --duration 0.1 --visualize
.venv/bin/python scripts/pace/data_collection_mujoco.py --no-visualize
```

Set `run.visualize = true` in TOML, or enable/disable it explicitly with the mutually exclusive `--visualize` / `--no-visualize` flags. Omitting both preserves the file setting. This does not change `plot`; use `plot = false` when only the live viewer is wanted. Live viewing needs a working desktop/GL context (tested on Linux with MuJoCo 3.17.0).

The viewer runs in its own process with its own model/state and allows camera adjustment. GUI control or physics changes cannot affect collected data. The first view uses the initialized state; subsequent state copies follow integration. Display publication is capped at 30 Hz and uses only the latest pending state. Collection is paced approximately in real time while the window is open. A slow display may skip frames; physics steps, measurements and timestamps are never dropped or changed.

Closing the window continues the full collection headlessly, without real-time waiting. Startup failure or unexpected viewer death aborts the run and preserves previous output. Startup waits at most 10 seconds; cleanup waits 2 seconds gracefully, then up to 1 second after terminate and 1 second after kill. These limits are internal constants. Data are saved only after viewer cleanup succeeds; Ctrl+C cancels with exit code 130. Disabling visualization avoids GUI imports, child processes and real-time waits entirely.

## Initial state and sample meaning

Physical leg positions start at the first normalized, direction-signed target plus encoder bias; wheel angles and all joint velocities start at zero. Native command histories are filled with the starting leg targets plus bias and zero wheel-speed targets. No settling interval is added; startup transients are included.

For the supplied model, `dt=0.0025 s` (400 Hz), actuator delay is `0.010 s` and history capacity is four samples. Each row records refreshed **pre-integration** sensor readings and the original command at `time[k]=k*dt`. Desired signals have not passed through actuator delay. There are `N=duration/dt` rows covering `[0,duration)` and N physics steps; the state at the endpoint is not an extra row.

## Saved tensors

The `.pt` file contains exactly five CPU tensors, readable with `torch.load(path, weights_only=True)`:

| Key | Shape | Dtype | Unit |
| --- | --- | --- | --- |
| `time` | `[N]` | float64 | s |
| `dof_pos` | `[N,12]` | float32 | rad |
| `des_dof_pos` | `[N,12]` | float32 | rad |
| `dof_vel` | `[N,4]` | float32 | rad/s |
| `des_dof_vel` | `[N,4]` | float32 | rad/s |

Measured fields include bias/noise as described above; desired fields are issued commands before native delay. Channel ordering follows the configuration. The file does not contain additional metadata: keep the matching TOML and MJCF when interpreting a dataset. A matching mixed task must declare the same leg/wheel column order; an ANYmal pure-leg task cannot fit the wheel fields. Fitting settings declare reference semantics; no sidecar is generated.

## Plot

```bash
.venv/bin/python scripts/pace/data_collection_mujoco.py --duration 0.1 --plot
```

After saving, Matplotlib shows twelve leg-position subplots and four wheel-speed subplots in separate figures. Each compares the recorded measurement with its pre-delay desired signal. Plotting does not resample noise. The live viewer described below is independent of these post-run plots.

## Errors and physical acceptance

Invalid configuration, missing or unsupported channels, invalid dynamics warnings, nonfinite data and evidence of a simulation time reset cause a nonzero exit. The last physics step is checked too. Fix the reported input/model problem and rerun; old output remains intact. An interrupt exits with code 130. Inspect the preceding “Saved” message if plotting later fails.

Collision geometry and trajectory suitability are evaluated by the model owner. The current supplied model showed initial base-to-hip contacts in a short research probe. The collector neither excludes those contacts nor treats tracking error/contact as a software failure. A successful dataset is not evidence of accurate physics, collision-free motion, full-sweep stability or identification quality.

## Development checks

Tests use public configuration, collection, save, plotting and CLI interfaces. Minimal native models exercise delay, timing, saturation and fault paths; X5 smoke tests require the local model resources. If those resources are absent, only those smoke tests are skipped.

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 .venv/bin/pytest tests/test_mujoco_collection.py -q
```

Disabling automatic pytest plugin loading isolates these tests from unrelated system plugins (for example a ROS installation with missing optional test dependencies).
